## Common accounting boundary

`research_runner.run_slot` verifies a preregistered primary task, its exact assets
and the exact candidate before entering the official `run_agent_sandbox` path.
The official session start timestamp starts the shared 300-second ledger.
The enclosing CPU child is limited to 330 seconds, including imports, setup and
cleanup; that envelope never extends the agent's active work allowance.
The original 30-tool and 60-second command limits remain in the official context.
The receipt's `cleanup_seconds` measures the final manager close; total child
wall time also includes the official runner's sandbox teardown and gateway stop.

The loopback gateway admits at most 50 total upstream requests across root,
delegate, retries and compaction. It preserves explicit frozen sampling and
fills the same fixed temperature, top-p and output allowance when the official
compactor omits generation configuration. A conflicting explicit value is rejected.
The thinking bridge remains enabled. The actual seed is recorded, including null.
Context cache configuration remains min_tokens 2048, TTL 1800 seconds and interval
10; compaction remains interval 15, overlap 2, threshold 14336 and retention 5.
Server prefix-cache behavior is unmeasured on these CPU fixtures.

Every admitted request, including a failed HTTP attempt, consumes the same
allowance. Streaming requests ask for a final usage object. Prompt, completion,
reasoning and cached counts are collected; reasoning is a subset of completion,
never added twice. Missing, duplicated, inconsistent or truncated usage remains
unknown and blocks a complete token-accounting claim. Streaming reads use the
remaining work time even after an upstream close header; teardown closes in-flight
upstream sockets. Concurrent 80-attempt regression tests admit exactly 50.
