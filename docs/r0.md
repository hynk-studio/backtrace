## R0 is not yet frozen

The requested combination of **notebook v2 with only its sampling adjustment**
and **no LoRA** is inconsistent with the acquired sample. Root `agent.yaml`
declares `adapter: main_lora`; `sub_agents/code_analyzer.yaml` declares
`adapter: tool_lora`. Each has a real PEFT directory with JSON metadata and
safetensors weights. Official discovery returns both adapter names. Notebook
v2 copies them, discovers them and passes them to its model server.

Notebook cell `63cb4756` writes temperature 0.2, top_p 0.95, max_output_tokens
16384, thinking_budget 4096 and include_thoughts true, omitting thinking_level.
Its literal UTF-8 output matches the acquired `configs/sampling.yaml` **exactly**
(120 bytes). Thus this sampling rewrite makes zero byte changes to this acquired
sample; that observation does not turn its adapter-equipped recipe into no-LoRA.

Proposed owner decision: retain notebook v2 as the provenance reference, remove
only the two adapter declarations and omit `adapters/` in a separately generated
no-LoRA variant. Preserve every other starter byte and its existing AgentTool.
This deviation is **not approved or implemented** in this checkpoint. No diagnostic
prompt, new skill, extra agent hierarchy or custom reasoning engine is proposed.
`baseline` deliberately exits 2 and creates no archive while this choice is open.

## Contract resolved and discrepancies preserved

- Official imported limits: 3,221,225,472 unpacked bytes (implementation accepts
  equality), 10,000 files, 1,000 YAML files, 50 MiB YAML/skill limits, 500 agents,
  depth 50, 1,000 skills, loop limit 500; generation output 1..32768, thinking 0..32768.
  Allowed suffixes: `.yaml`, `.yml`, `.md`, `.txt`, `.py`, `.json`, `.safetensors`.
  Adapter suffix: `.safetensors` only. These do not replace the local inspector's caps.
- The guide says exactly one of four conventional root names. Actual 0.2.11
  discovery prioritizes `agent.yaml`, then `root_agent.yaml`, then a lone root YAML.
  R0 will keep `agent.yaml` at ZIP root regardless of this discrepancy.
- `!include` is relative to the including YAML's directory and must resolve within
  the submission root. The guide's blanket ban on `..` does not match the loader:
  the starter's `../prompts/analyzer.md` and `../configs/sampling.yaml` pass.
  Symlinks and escaping paths are rejected. YAML recursion is bounded at depth 10;
  explicit cycle detection is not present in this loader. Do not generalize this
  behavior to `config_path`, which has separate traversal checks.
- The acquired optional `eval_config.yaml` sets command timeout **60 seconds**,
  tool calls **10**, agent time **1 minute**, turns **50**. Guide examples use 300
  seconds. Preserve actual sample budgets; do not substitute guide defaults.
- Guide hosted serving uses GPU memory 0.80 and compaction interval 5; notebook
  v2 uses 0.90 and 15. Both use context 32768. These are separate recipes; neither
  was executed here. Per-task agent time excludes setup, whereas the overview's
  aggregate 12-hour budget includes it; these measure different intervals.
- No-LoRA is permitted by the overview and optional adapter schema. The current
  sample is nevertheless adapter-equipped. Sample adapter metadata: PEFT LORA,
  rank 4, alpha 8, layer 0, q_proj/o_proj, revision null. Metadata and successful
  discovery do not establish trained content, useful effect or runtime compatibility.
- Notebook explicitly selects model asset `Other/.../2`. The package's model-path
  helper has a default version 1 and fallback search; do not rely on that helper
  to pin a later smoke run. No checkpoint/tokenizer/template bytes were acquired.
