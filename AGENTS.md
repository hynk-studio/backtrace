# Backtrace working agreement

Backtrace is independent research, not Augnes product development. Work only in
this repository. Read current origin, branch/base/head, status, issue and PRs
before modifying or publishing. Preserve unrelated changes; never force-push.

- ChatGPT owns the hypothesis, planning, evidence interpretation and PR review.
- Codex owns current-source inspection, assumption challenges, implementation,
  tests and the requested Draft PR.
- The human owns merges, account/model/competition terms, real submissions and
  paid compute. Do not merge, enable auto-merge or close Issue #1.

Use issue-scoped feature branches and one Draft PR per authorized task. Keep
substantive changes off main. The empty bootstrap commit was solely a PR base;
that exception is consumed. Reference issues without automatic closing keywords.

Read primary competition sources before implementing their contract. Generic
ADK documentation and search snippets are not a competition schema. Record URL,
access time, artifact/version, SHA-256 for acquired bytes and evidence level
(primary text, search-index snippet, observed execution). Distinguish organizer
code and published output from execution performed here. Preserve conflicts and
unknowns; do not label generic ZIP inspection as official validation.

Run `python3 -m unittest discover -s tests -v` and CPU preflight for tooling
changes. Separately report local tests, official contract/starter acquisition,
candidate packaging/inspection, official validation, permitted end-to-end tasks,
Kaggle acceptance and hosted scoring. Mark unrun stages NOT RUN.

Use local/free CPU only for this task. No paid APIs, GPU rental, long training,
large model downloads, rule acceptance or submission. Prepare a capped proposal
before any later paid probe. Never expose secrets or commit credentials, model
weights, downloaded data, generated outputs or third-party artifacts without
verified redistribution permission. Do not implicitly choose a license. Kaggle
public-sharing obligations require human review before competition participation.

Keep checkpoint, harness, tools, task families and total inference budget matched
across R0/R1/R2/R3; count diagnostics, retries and inspections. R3 feasibility does
not require positive R2 results. Large training requires verified compatibility,
a tiny-batch step, save/reload and runtime attachment first. Training-specific
claims need a matched general-reasoning training control.

Evaluator-only answers, latent causes, future observations and hidden labels must
never enter agent inputs. Split synthetic tasks by underlying world/problem
family. Never use hidden evaluation cases or leaderboard feedback as labels.
Do not invent calibrated probabilities for real repository diagnoses. Keep
synthetic competence separate from software-engineering transfer.
